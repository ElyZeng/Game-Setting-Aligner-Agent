Stage 4 round 4 (2026-11-12, branch fix/death-stranding-2-upscale-screen-mode) - code fix for the two
open mismatches; blast-radius checked against HZD/SotTR first
- Before writing any fix, checked whether the shared generic registry-JSON parser's screen_mode /
  UpscaleMethod / UpscaleQuality logic (config_manager/settings_parser.py's _parse_registry_json,
  reused verbatim by Horizon Zero Dawn Remastered and Shadow of the Tomb Raider via the same
  _registry_parse parser_fn) had ever actually been live-validated for those two titles. Grepped both
  titles' own COLLECT.txt for "Upscal|PICO|DLSS|FSR|CAS|XeSS" - zero matches in either file. Conclusion:
  this enum was never confirmed against live in-game UI text for HZD/SotTR either, in either direction -
  not proof it's wrong for them, just proof it was never checked. Given that, the fix below is scoped
  ONLY to Death Stranding 2 (via a game_hint check), so HZD/SotTR's unverified-but-so-far-unquestioned
  behavior is left completely untouched rather than risking a regression based on an assumption.
- Root cause found: _parse_registry_json already accepted a game_hint parameter but never branched on
  it anywhere in its body, AND the profile-first dispatch path (config_manager/profile_functions.py's
  shared _registry_parse wrapper, used by all three registry-based profiles) never actually passed a
  game_hint through at all - so this parameter was previously a complete no-op for every registry-based
  title, not just DS2.
- Fix: added a new game_hint="death stranding 2"-scoped branch inside _parse_registry_json covering
  the two confirmed-wrong values:
  - screen_mode: Fullscreen=1/ExclusiveFullscreen=0 now returns "Fullscreen" (was "Borderless
    Fullscreen"), matching the live Display Mode row read in round 2. ExclusiveFullscreen=1 still
    returns "Exclusive Fullscreen" (unchanged) - that raw state was never actually live-confirmed for
    DS2, kept as the least-assumption fallback rather than guessed further.
  - upscaling / upscaling_mode: UpscaleMethod=1 now returns "PICO" (was "DLSS"), UpscaleQuality=3 now
    returns "Dynamic" (was "Quality") - the only two raw values actually live-confirmed via VLM/OCR in
    round 2. Deliberately did NOT fabricate a full 0-4 mapping from PCGamingWiki's alphabetically-listed
    DLSS4/FSR4/FSR3.1/XeSS2/PICO option set, since that ordering is not proven to match the game's real
    enum order - any other raw UpscaleMethod/UpscaleQuality value now falls through to an honest
    "Method N"/"Mode N" placeholder instead of asserting a guessed label.
  - Added a dedicated parser_fn (config_manager/profile_functions.py's
    _death_stranding_2_registry_parse, registered as "death_stranding_2_registry_parse") instead of
    adding a parameter to the shared _registry_parse, so this fix cannot affect HZD/SotTR's dispatch at
    all even if the game_hint plumbing has a bug - death-stranding-2.json's parser_fn field now points
    at this new wrapper instead of the shared "registry_parse" id.
  - Also added DS2 (and, since the same gap applies, HZD/SotTR) to setting_options_for_game()'s
    per-game screen_mode branch so the dropdown includes "Borderless Fullscreen"/"Exclusive Fullscreen"
    (HZD/SotTR, unchanged parser output) or "Fullscreen"/"Exclusive Fullscreen" (DS2, new parser output)
    - previously a read value for any of these three titles could come back as a string not present in
    its own available_options list.
- Verified with a standalone manual script (pytest itself is not installable in this sandbox - no
  outbound pypi.org access, same restriction as github.com) exercising extract_key_settings(),
  _parse_registry_json() with and without the game_hint, setting_options_for_game(), and
